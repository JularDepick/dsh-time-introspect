# 耗时反思机制

面向插件维护者的机制说明. 用户视角的使用方式见 [README](../README.md).

## 设计目标

在超时发生的时刻, 把分散的耗时数据聚合为一份可定位的反馈送达模型, 并让反思行为本身参与成本核算. 插件只做三件事:

1. 在正确的时刻送达完整的耗时分布
2. 在反思不划算时主动休眠
3. 在模型自己觉得需要时可以被重新唤醒

## 数据来源

全部数据来自官方会话事件日志, 不写入任何自定义事件类型, 也不依赖插件私有存储:

| 事件 | 用途 |
|:---:|:---|
| `turn/start`, `turn/end` | 轮次边界与实际耗时 |
| `tool/call`, `tool/result` | 按 `callId` 配对得到单次工具耗时 |
| `user/message` | 识别本插件注入的反思提示与休眠通知 |
| `tool/call` 的 `arguments` | 读取 `task_estimate` 的预估与 `resume_reflection` 的自述原因 |

事件信封上的 `time` 是唯一时间戳来源; 事件载荷内没有现成的耗时字段.

## 折叠状态

插件通过 `ctx.sessionProjections` 注册一个 host-only 投影单元, 把上述事件折叠为逐会话状态:

- 每轮记录: 开始与结束时间, 预估, 按工具聚合的耗时, 工具调用数, 反思开销, 注入时刻与窗口状态
- 跨轮状态: 反思状态机, 冷却剩余轮数, 冷却累计次数, 连续高占比轮数, 保守阈值剩余轮数, 待发休眠通知, 重启原因与待用前缀, 是否已注入过

投影单元只做同步纯折叠; 与单元无关的事件返回同一状态引用. 状态在进程重启后由日志重放自动重建. 完成轮次按 `maxTurnHistory` 截断, 未配对的工具调用在轮次结束时清空.

## 时间口径

- 实际耗时 = `turn/end.time - turn/start.time`
- 工具耗时 = `tool/result.time - tool/call.time`, 覆盖审批等待与会话排队
- 反思开销 = 注入消息进入日志的时刻到反思阶段结束
  - 结束点是 `report_reflection_cost` 的结果, 或反思后第一个普通工具调用的开始, 先到者为准
  - 轮次结束时窗口仍未关闭则不记入, 避免把整轮模型时间算成反思成本
- 模型自身处理 = `max(0, 实际 - 工具耗时 - 反思开销)`

崩溃恢复会合成 `step/end` 与 `turn/end` 并复用最后事件时间, 因此零时长轮次被显式排除在判定之外.

## 注入判定

在 `agent/pre-step` 上以 `prepend: true` 注册监听器, 先 `await next()` 委派下游, 再按以下顺序决定:

1. 下游拒绝或信号中止: 不动
2. 不是 step 1: 不动
3. 批次里已有本插件消息: 不动
4. 状态为休眠且有待发通知: 注入一次休眠通知
5. 状态为冷却或休眠: 不动
6. 找到当前轮之前最近的已闭合轮次, 没有预估则不动
7. 实际耗时为零, 或超出量不同时满足比例与绝对下限: 不动
8. 其余情况注入耗时反思

注入消息使用插件名作为 `source.kind`, `form` 为 `snapshot` 或 `notice`, 进入日志后成为持久的 user 消息. 插件不阻断工具调用, 不检查模型是否采纳.

## 自约束

在 `turn/end` 时结算:

- 反思占比 = 反思开销 / 实际耗时
- 阈值 = 保守期内 `coolRatioAfterResume`, 否则 `coolRatio`
- 改善判定: 本轮实际耗时相对前序已完成轮次实际耗时的中位数下降 `minImprovementRatio` 以上
- 占比高于阈值且无改善时累加连续计数, 否则清零
- 连续计数达到 `coolAfterHighTurns` 时:
  - 累计冷却次数达到 `dormancyAfterCooldowns`: 进入休眠, 标记一次性通知
  - 否则进入冷却, 时长 `coolTurns * 2^(已冷却次数)`, 上限为 `coolTurns * 8`
- 冷却中每闭合一轮递减剩余轮数, 归零后回到 active
- 休眠期间不累计反思开销, 普通工具耗时照常记录

`resume_reflection` 的调用事件本身触发状态迁移: 回到 active, 冷却计数清零, 保守阈值生效 `conservativeTurns` 轮, 自述原因保留到下一次反思注入时作为前缀呈现.

## 已知限制

- 分叉会话的继承前缀不会重放, 投影从新会话自身的事件开始累加; 分叉后的第一个存活轮次没有可比的前序轮次, 因此不会立即触发反思
- 每个子代理会话独立折叠, 父会话与子代理的耗时不会互相合并
- 崩溃恢复产生的合成 closer 复用最后事件时间, 零时长轮次被显式跳过
- 反思窗口依赖注入消息进入日志; 注入后在同一轮内没有任何工具调用时, 反思开销记为 0, 不做整轮折算
- 预估按轮次归属; 一轮多次登记以最后一次为准, 上一轮没有登记时下一轮不注入

## 源码地图

| 文件 | 职责 |
|:---:|:---|
| `src/index.ts` | 插件入口: 装配投影与工具, 注册 pre-step 监听器 |

| `src/types.ts` | 消息来源与投影状态的类型声明合并 |

## 测试

单元测试覆盖:

- 注入阈值(比例, 绝对值, 无预估, 冷却, 休眠)
- 自约束状态机(冷却触发, 倒计时, 翻倍, 休眠, 重启后保守阈值, 改善判定)
- 投影折叠(工具聚合, 预估解析, 反思窗口, 休眠分桶, 历史截断, 零时长轮次)
- 注入时机(step 1, 下游拒绝, 中止, 去重, 无状态)
- 工具参数校验与结果渲染
- 中英文文案

测试使用最小假 Context, 不依赖完整运行时.
